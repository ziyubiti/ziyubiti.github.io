5G 国密改造：完整密钥派生链路解读

Sep 17, 2026 | 6G | 次阅读

　　上一篇文章拆了5G注册流程的安全激活分界点，这篇看一个工程落地问题：5G网络如何做国密改造。方案基调是”空口PDCP用ZUC(NEA3/NIA3) + KDF换SM3-HMAC + 身份加密/SUCI换SM2”，且不改动PDCP层协议结构。整个改造涉及一条从USIM卡到空口的完整密钥派生链路，下面按层拆解。

1. 改造点总览：三换两不换

  • SM2 替换：SUCI生成（SUPI加密）与网元证书签名，替代ECIES/ECDSA；
  • SM3-HMAC 替换：各级KDF密钥派生（K_ausf/K_amf/K_gNB），替代HMAC-SHA256；
  • ZUC 国密原生：空口PDCP加密/完整性（NEA3/NIA3）本就是3GPP标准算法，不需要改；
  • 不变之一：SUPI分配与根密钥K，仍是开户制卡阶段一次性预制；
  • 不变之二：5G AKA主认证流程，USIM内部基于K计算RES*、生成CK/IK的MILENAGE/TUAK算法不变。

2. 密钥派生链路：从第0层到第5层

　　第0层是开户与制卡：SUPI（imsi-MCC+MNC+MSIN）由UDM分配、烧录进USIM芯片，运行期只读。第1层在USIM卡内部：根密钥K固化、AKA主鉴权生成CK/IK，以及关键的SUCI生成——用归属网络公钥加密MSIN，标准方案是ECIES(Curve25519/P-256)，国密替换为SM2加密。第2层回到UE协议栈（不在卡内）：CK/IK参与派生K_ausf、K_amf，国密方案是SM3-HMAC替换HMAC-SHA256，只需UE固件升级、不换卡；NAS密钥K_NASenc/K_NASint用ZUC原生支持。第3层是核心网（AUSF/UDM/AMF/新增SIDF）：SIDF用SM2私钥解密SUCI还原SUPI，AUSF/AMF侧KDF同步换SM3-HMAC，证书换SM2国密证书。第4层gNB基站：K_gNB派生换SM3-HMAC，RRC密钥与用户面密钥均用ZUC。第5层空口最终输出：SRB1/SRB2信令与DRB用户面数据在PDCP层完成ZUC(NEA3)加密+NIA3完整性保护。

3. USIM卡影响：只有一处要换卡

　　整条链路里，唯一涉及换卡的是SUCI生成环节——存量硬件USIM芯片算法固定、不支持SM2，需要更换国密USIM卡；软SIM/工业模组则可通过固件升级支持。根密钥K、AKA鉴权算法、SUPI全部不动；KDF派生发生在UE协议栈而非卡内，SUPI只是输入参数；空口ZUC加密由终端和基站原生支持。换句话说，换卡成本集中在一次SM2能力升级上，其余改造都在网络侧和终端固件侧。

4. 风险清单

　　高风险：① SUCI国密改造的换卡成本与工期；② KDF换SM3-HMAC要求UE与核心网严格同步部署，输入参数（含SUPI）完全一致，任何一侧不一致直接注册失败；③ 密评认可度——个别密评单位要求PDCP加密必须用SM4，与本方案（ZUC）冲突，需提前确认。中风险：老旧工业模组可能不支持NEA3/NIA3，需盘点终端能力；SIDF需新增SM2解密与私钥管理；网元间国密TLS要求全链路网元支持SM2/SM4套件。低风险：SUPI/根密钥K不变、AKA流程不变、空口ZUC为3GPP标准算法。

⚠ 高风险点
1. SUCI国密改造（SM2）：存量硬件USIM卡芯片内部算法固定，不支持SM2加密运算，批量更换USIM卡会带来较高成本、换卡工期、现场换卡运维工作量；软SIM工业模组可固件升级规避该问题。
2. KDF替换为SM3-HMAC：UE侧和核心网侧必须严格同步部署，KDF输入参数（含SUPI）完全一致，任何一侧算法不一致，密钥推导结果不同，直接导致终端注册失败。
3. 密评认可度：提前和密评专家确认算法清单，个别密评单位会要求PDCP加密必须使用SM4，此时当前方案不满足。
⚡ 中风险点
1. 终端兼容性：部分老旧工业模组不支持ZUC(NEA3/NIA3)，需要提前盘点所有终端能力，不支持的模组需要更换。
2. SIDF模块改造：核心网SIDF需要新增SM2解密能力，配套SM2国密私钥管理，密钥安全保管是重点。
3. 网元间国密TLS：N2/N8/N12接口如需国密TLS，所有网元都要支持SM2/SM4套件。
✓ 低风险/无风险
1. SUPI、根密钥K：全部保持原有预制值不变，不需要重新制卡、开户。
2. 5G AKA认证流程：USIM内部鉴权算法不变，认证交互流程完全不变。
3. 空口ZUC加密：3GPP标准算法，主流基站、工业模组原生支持，NAS/AS Security Mode Command协商逻辑不变。
4. SUPI参与KDF：SUPI作为KDF输入参数，不管是SHA256还是SM3-HMAC，输入逻辑不变，不需要改动业务逻辑。
更新后一句话总结
SUPI是开户制卡阶段一次性写入USIM的永久身份标识，运行期只读；每次注册时USIM读取SUPI，经SM2加密得到SUCI发给核心网SIDF解密还原SUPI。 本方案（ZUC空口 + SM3-HMAC做KDF + SM2做SUCI加密），唯一需要更换实体USIM卡场景：使用硬件USIM且开启SM2-SUCI加密；SUPI本身、根密钥K、AKA鉴权、KDF派生、空口ZUC加密，全部不需要换SIM卡。
